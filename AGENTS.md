# devjobs

Standard Flutter scaffold (SDK `^3.12.1`, Material Design). Single entrypoint at `lib/main.dart`.

## Commands

| Action | Command |
|--------|---------|
| Run (debug) | `flutter run` |
| Run (release) | `flutter run --release --no-tree-shake-icons` |
| Analyze | `flutter analyze` |
| Test | `flutter test` |
| Get deps | `flutter pub get` |
| Clean build | `flutter clean` |
| Build Android (APK) | `flutter build apk --release --no-tree-shake-icons` |
| Build Windows | `flutter build windows --release --no-tree-shake-icons` |
| Build Linux | `flutter build linux --release --no-tree-shake-icons` |
| Install Linux (local) | `./scripts/install-linux.sh` |
| Build con datos de compilación | `./scripts/build.sh linux` · `linux-install` · `windows` · `apk` |
| Run con datos de compilación | `./scripts/build.sh run` |
| Subir versión | `./scripts/bump-version.sh [build\|patch\|minor\|major]` |

> **`--no-tree-shake-icons` es obligatorio en release.** El tree-shaker de íconos
> de Flutter tiene un bug que descarta glyphs usados (p.ej. `Icons.business_outlined`,
> `Icons.apartment`) y quedan **en blanco** en release. Sin el flag la fuente se
> recorta a ~6 KB; con el flag se embebe completa (~1.6 MB) y ningún ícono falla.
>
> **`scripts/build.sh` para los builds que se distribuyen**: inyecta `GIT_COMMIT`,
> `BUILD_TIME` y `BUILD_DIRTY` con `--dart-define` e incluye el flag de íconos.
> Sin el script, Ajustes → Acerca de muestra "No disponible" en commit y fecha.

## Build / Deploy

- **Versionado (obligatorio al terminar cambios):** la versión visible sale SIEMPRE del `pubspec.yaml` (`version: X.Y.Z+N`; `package_info_plus` la lee tal cual) y **nunca se auto-incrementa al compilar**. Al terminar cualquier cambio de código que se vaya a compilar o distribuir, ejecutar `./scripts/bump-version.sh` antes de `scripts/build.sh`: por defecto suma 1 al build number (`N+1`); `patch`/`minor`/`major` suben el nombre y dejan el build en +1 (usar `minor` cuando la tanda agrega funcionalidades, `patch` para arreglos, `major` para cambios grandes). El script imprime `X.Y.Z+N → …`; no editar la versión a mano salvo salto puntual. Un agente de IA que entregue cambios compilables debe dejar la versión subida como parte del cambio.

- **Android APK** → `build/app/outputs/flutter-apk/app-release.apk`; instalar en dispositivo conectado con `flutter install --release`.
- **Windows** → `build/windows/x64/runner/Release/devjobs.exe`; para distribuir copiar **toda la carpeta `Release\`** (exe + DLLs + `data\`). La plataforma se habilitó con `flutter create --platforms=windows .` (carpeta `windows/` ya existe). Ventana 420×880 centrada (`windows/runner/main.cpp`); ícono generado desde `assets/icon/icon.png` vía `flutter_launcher_icons` (config `windows.generate`).
- **Instalador Windows (opcional)** → `installer/devjobs.iss` (Inno Setup 6): compilar con `ISCC.exe installer\devjobs.iss` → `installer/Output/DevJobsSetup.exe` (requiere `flutter build windows --release` previo).
- **Linux** → `build/linux/x64/release/bundle/` (binario + `data/` + `lib/`); para distribuir copiar **toda la carpeta `bundle/`**. Requiere toolchain `clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev`. Ventana 420×880 centrada y mínima 360×600 (`linux/runner/my_application.cc`); ícono de ventana desde `linux/devjobs.png` (256×256, copiado al bundle por `linux/CMakeLists.txt`). `APPLICATION_ID=com.example.devjobs`.
- **Instalación Linux (sin sudo)** → `scripts/install-linux.sh` copia el bundle a `~/.local/opt/devjobs`, symlink en `~/.local/bin/devjobs`, `.desktop` en `~/.local/share/applications` e ícono en `~/.local/share/icons/hicolor/256x256/apps`; `--uninstall` revierte. Plantilla del entry: `linux/devjobs.desktop`.
- Web → `build/web/` (opcional: requiere habilitar `web/` con `flutter create --platforms=web .`). Todos los artefactos quedan bajo `build/` (gitignored).
- El `.env` (con `API_URL` y, opcionalmente, `AI_API_KEY`) se embebe en el bundle: debe existir antes de compilar. Las variables de IA son solo la **semilla** inicial; la config real se edita en la app. Ver README → Despliegue.

## Config

- `analysis_options.yaml` — default `package:flutter_lints/flutter.yaml`, no overrides.
- `.env` — **local, gitignored**. Obligatoria `API_URL`; opcionales `AI_API_KEY`, `AI_BASE_URL` y `AI_MODEL`. Son la **semilla** de `kAiConfig`: si el usuario nunca guardó una configuración, la app arranca con esos valores; si la guardó (Ajustes → Importación con IA), la guardada manda. `AI_MODEL` admite uno o varios modelos separados por comas (`kAiModels`; el primero es el principal). Sin clave no se renderiza `ImportEntryCard`. `.env.example` (versionado) documenta las tres variables.
- `opencode.json` — **local, gitignored** (no se versiona: contiene rutas absolutas por SO). Habilita el MCP server `dart-mcp-server` (análisis/LSP, hot reload, pub). En Linux/Ubuntu usa ruta absoluta al SDK (`/home/felipe/Documentos/flutter/bin/dart`) porque `dart` no está en `PATH`; en Windows basta `dart`. Plantillas listas para copiar/pegar en README → «MCP de Dart en OpenCode».
- `skills-lock.json` — **versionado**; declara las **8 skills** del proyecto (los archivos viven en `.agents/`, que está gitignoreado). Set: `find-skills`, `grill-me`, `dart-add-unit-test`, `dart-run-static-analysis`, `flutter-add-widget-test`, `flutter-use-http-package`, `flutter-fix-layout-issues`, `flutter-build-responsive-layout`. Restaurar tras clonar: `npx skills experimental_install`. Ver README → «Skills».

## Architecture

- **Data source:** Google Sheets via Apps Script Web App (REST API).
  - `apps_script_code.example.gs` — reference copy of the deployed script.
  - `.env.example` — template; copy to `.env` and set `API_URL`.
  - **Fechas:** la app envía `yyyy-MM-dd` (`formatApiDate`) y lee `d/M/yyyy`. El script convierte a `Date` real con la zona de la hoja (`getSpreadsheetTimeZone()`) y nunca escribe strings de fecha con `setValue`. `GET ?action=meta` (solo lectura) reporta zona, locale, formato de A/K, primera fila de datos y rango del filtro; si `timeZone` y `scriptTimeZone` difieren, igualar la zona del proyecto de Apps Script a la de la hoja. Tras cambiar el script, redesplegar con **Manage deployments → Edit → New version** para conservar la URL.
  - **Creación:** `createRow` rellena el hueco inmediato sobre la primera postulación si la fila está realmente vacía (sin valores, fórmulas ni notas) y devuelve `shifted: false`; si no hay hueco, inserta una fila y devuelve `shifted: true`. Las nuevas quedan encima de las anteriores.
  - **Análisis IA de empresas:** pestaña `EmpresaAnalisis` (una fila por empresa, clave = nombre normalizado minúsculas/trim). `GET ?action=companyInsights` lista los análisis y `POST upsertCompanyInsight` guarda/actualiza por empresa (crea la pestaña si no existe). Fechas `fechaAnalisis`/`datosAl` con el mismo contrato `formatApiDate`/`parseDateForSheet`. Los scripts viejos no conocen la acción: `fetchCompanyInsights` descarta filas sin forma de análisis y devuelve `[]`.
- **State management:** `Provider` (`ChangeNotifier`). Single `AppState` in `lib/providers/app_state.dart`.
  - Cache with 3-min TTL — invalidated on refresh or status change.
  - `createApplication(JobApplication)` hace POST `create`. Con `shifted == false` (se rellenó un hueco sin mover filas) inserta en la caché local y no refresca; con `shifted == true` invalida el TTL y fuerza `fetchApplications(forceRefresh: true)` antes de volver. `updateApplication` también parchea `fechaPostulacion`/`fechaSeguimiento`.
  - Análisis IA de empresas: mapa `_insights` por clave normalizada (`insightFor`), `loadCompanyInsights()` (caché local + Sheet, merge; los fallos de red no marcan offline ni tumban la app), `analyzeCompany(nombre)` (genera con `CompanyAnalyzerService` — inyectable vía `analyzerBuilder` para tests — guarda en `LocalCache` y hace `upsertCompanyInsight`; si el guardado en la Sheet falla se conserva local), `analyzingInsight` / `insightError` / `clearInsightError()`. `isInsightStale` (helper) avisa cuando hay postulaciones o novedades nuevas desde `datosAl`/`totalPostulaciones`.
  - `mergeCompanies({finalName, names})` (combinar empresas): renombra la columna `empresa` de las filas absorbidas (`mergeRenameTargets`: solo filas cuyo nombre no es exactamente el final) vía `updateRow` y fuerza `fetchApplications(forceRefresh: true)`. **No toca los análisis IA**: el del nombre final queda tal cual (y se marca desactualizado al cambiar los conteos); los de nombres absorbidos quedan huérfanos en `EmpresaAnalisis`.
  - Dashboard stats computed locally from cached list.
  - Dashboard cards: Total postulaciones (no click), Activas (clickable → `openApplications(filterActivas)`), Con entrevista (no click; cuenta `entrevistaRealizada`, el switch de la columna N), Finalizadas (clickable → `openApplications(filterFinalizadas)`). Clickable cards show `chevron_right` indicator.
  - Tasa de conversión: tres barras. "Con respuesta" = estados distintos de Enviada, Sin respuesta y Retirada (`hasResponse`, columna H); "A entrevista" = switch N (`entrevistaRealizada`); "Finalizadas" = estados terminales.
  - Actividad reciente (`lib/widgets/recent_activity_card.dart`): conteos de últimos 7/30 días por `fechaPostulacion` y hasta 3 movimientos ordenados por `fechaSeguimiento` (fallback `fechaPostulacion`); cada fila abre el detalle.
  - Pipeline (`lib/widgets/pipeline_card.dart`): barra + leyenda; cada etapa es tocable y abre `FilteredApplicationsScreen(selector: applicationsInStage)`. La lógica de etapas vive en `lib/helpers/pipeline.dart` y usa el mismo orden general (`application_sort.dart`).
  - Ritmo mensual (`lib/widgets/monthly_trend_card.dart`): últimos 6 meses por `fechaPostulacion`, con meses en cero; la lógica vive en `lib/helpers/trends.dart`.
  - Salario ofrecido (`lib/widgets/salary_insights_card.dart`): tabla por moneda (COP/USD) con promedio y rango. `parseSalary` interpreta valores únicos y rangos, detecta USD/COP y excluye "yo puse/puse/propuse/sugerí"; `formatCompactSalary` abrevia (5,9M/100K/1,3K); `salaryInsights` agrupa por moneda. Si solo hay una moneda, la tarjeta usa una fila compacta sin encabezado.
  - Agenda (tab 3): `AgendaScreen` + `AgendaSectionCard`; secciones **Por gestionar**, **Entrevistas agendadas** y **Ofertas recibidas** (precedencia en ese orden, sin duplicados). El badge de la barra usa `agendaCount`; "Ver todas" abre `PendingApplicationsScreen` o `FilteredApplicationsScreen` con selector.
  - Distribución (dashboard): `DistributionCard` (`lib/widgets/distribution_card.dart`) con selector segmentado de ancho completo (Modalidades / Ciudades, por defecto Modalidades) y debajo solo el grupo activo. "Ver todas" abre `DistributionDetailScreen`; cada fila abre `FilteredApplicationsScreen`. Plataformas y Empresas no son segmentos: las plataformas tienen su propio botón/pantalla y las empresas su propia pestaña.
  - Plataformas (`lib/widgets/platforms_review_button.dart` + `lib/screens/platforms_screen.dart`): Inicio muestra un botón neutro "Revisar plataformas" (visible cuando hay alguna postulación con enlace) que abre `PlatformsScreen`. No es una alerta: no hay warning, badge ni umbral de días. La pantalla lista la última aplicación por plataforma con fecha exacta + relativa, con filtro propio por nombre (`_SearchField`, insensible a mayúsculas/tildes, contador "N de M plataformas" y empty state con "Limpiar búsqueda"; el resumen y el aviso de "sin enlace" se ocultan mientras se busca) y `PlatformSortBar` (Más postulaciones por defecto / Recientes / Más antiguas). Cada fila abre `PlatformDetailScreen` (detalle de la plataforma). Las postulaciones sin enlace se excluyen y la pantalla avisa cuántas quedaron fuera.
  - Detalle de plataforma (`lib/screens/platform_detail_screen.dart`, `PlatformDetailScreen(nombre)`): mismo lenguaje que `CompanyDetailScreen` — header (ícono `Icons.language`, total y última actividad), card **Métricas** (Activas, Respondieron `conNovedad/total`, Finalizadas, Entrevistas, Por gestionar y Prom. cierre condicional), card **Distribución** (Empresas / Ciudades / Modalidades; los chips de empresa son tocables y abren `CompanyDetailScreen`), card **Salario ofrecido** (`SalaryInsightsCard` con `salaryInsights`) y **Vacantes (N)** al final con `ApplicationCard` → `ApplicationDetailScreen`. Los datos vienen de `platformDetailStats` sobre `state.getByField('plataforma', nombre)`; sin datos muestra "Sin datos para mostrar".
  - "Por gestionar" flag (columna O del Sheet, checkbox): marca manual de vacantes con algo pendiente (la razón vive en `comentarios`). No se auto-limpia. Se alterna desde el AppBar del detalle o tocando el `GestionTag` en la card. No altera el orden de los listados: su lugar es la sección "Por gestionar" de Agenda.
  - Postulaciones filters (pills dentro de la pestaña, con contador): `filterAll` (Todas, por defecto), `filterActivas` = estado NOT IN (Enviada, Rechazada, Retirada, Aceptada); `filterEnviadas` = estado = Enviada; `filterFinalizadas` = Rechazada + Retirada + Aceptada; `filterPorGestionar` = flag manual (lo usan la sección "Por gestionar" de Agenda y `PendingApplicationsScreen`). Definición única en `_matchesFilter`, compartida por `getApplications`, `countApplications` y `dashboardStats`. Empresas = agrupación case-insensitive/trim de la columna `empresa` (`companiesStats`), ordenada por nº de postulaciones desc.
  - `diasProceso` computed getter on model: difference in days between fechaPostulacion and fechaSeguimiento (null when no seguimiento).
  - Detail screen shows "Tiempo del proceso" below "F. seguimiento" (only when available). El AppBar tiene el toggle "Por gestionar" (`label_important` / `label_important_outline`, siempre visible y deshabilitado offline) y un menú ⋮ (`PopupMenuButton`) con **Editar postulación** y **Agregar nota**: la nota abre `AddNoteDialog` y agrega `- d/M/yyyy: texto` a `comentarios`. Ambos ítems quedan deshabilitados sin conexión. Debajo del proceso, el botón **Cambiar estado** (siempre visible, también con el proceso cerrado) abre `ChangeStatusDialog` (`lib/widgets/change_status_dialog.dart`): todos los estados agrupados (Estado / Cerrar proceso, con el estado actual preseleccionado y los valores desconocidos incluidos), fecha de la novedad (hoy por defecto, editable y sin futuro), nota opcional y checkbox "Ya hice la entrevista" (columna N, se envía solo si cambió). Guardar queda deshabilitado si no hay cambios. Usa `changeStatusUpdates`: estado + `fechaSeguimiento` siempre, `comentarios` fechados con la fecha elegida si hay nota y `porGestionar: false` solo cuando el estado es terminal. El SnackBar anuncia "Proceso finalizado como X" (terminal) o "Estado actualizado a X".
  - Enlace externo: la sección va antes de comentarios y descripción. Muestra el dominio y botones **Abrir** (`url_launcher`, navegador externo) y **Copiar**; si el enlace no es válido, "Abrir" se deshabilita y aparece un aviso inline.
  - Tema: el ícono de ajustes del AppBar abre `ThemeSettingsSheet` (Sistema/Claro/Oscuro + fila **Importación con IA** + fila **Acerca de DevJobs**). `AppState.themeMode` aplica el cambio al instante vía `MaterialApp` y se persiste en `LocalCache`.
  - Versión y compilación: `lib/services/build_info_service.dart` compone `AppBuildInfo` (`lib/models/app_build_info.dart`) con versión/build de `package_info_plus` (lee `version.json` en Linux/Windows y el `PackageManager` en Android: siempre coincide con el `pubspec.yaml`) y con `GIT_COMMIT`/`BUILD_TIME`/`BUILD_DIRTY` que inyecta `scripts/build.sh` con `--dart-define`. `lib/screens/about_screen.dart` (Ajustes → **Acerca de DevJobs**) muestra commit, fecha, plataforma y canal + **Copiar información** y **Ver código en GitHub**; el tile `about-settings` ya muestra `vX.Y.Z (n) · commit`. Sirve para comparar la instalación con `git log -1 --oneline`: si el commit no coincide, falta compilar; un `*` indica cambios sin commitear. Helpers puros en `lib/helpers/app_build_info.dart`. Sin el script, commit y fecha quedan en "No disponible".
- **Importación con IA (opcional):** `lib/services/job_import_service.dart` hace fetch del enlace (UA de navegador, timeout 20 s), clasifica la página (`JobPageKind`: `detail`, `listing`, `spa`, `blocked`, `notAJob`) y solo entonces llama a `lib/services/fallback_extractor.dart` (`FallbackExtractor`: prueba los modelos de `AiConfig` en orden; si uno falla por cuota/no habilitado/no encontrado/servidor caído pasa al siguiente, con ~400 ms de pausa; red y JSON inválido **no** activan el respaldo; si todos fallan lanza un error que lista los modelos intentados) que envuelve `lib/services/openai_compatible_extractor.dart` (OpenAI-compatible; por defecto OpenCode Go + `deepseek-v4.1-flash`). La configuración vive en `lib/models/ai_config.dart` (`AiConfig`: `baseUrl` + `apiKey` + lista ordenada de `models`), se persiste en `LocalCache` (`devjobs_ai_config`) y se expone en `AppState.aiConfig` / `AppState.aiEnabled`; `kAiConfig` (de `config.dart`) es la semilla desde el `.env` cuando no hay nada guardado. Se edita en `lib/screens/ai_settings_screen.dart` (Ajustes → Importación con IA); sin configuración, `ImportEntryCard` no se renderiza y la hoja ofrece **Configurar IA**. Para DeepSeek se envía `reasoning_effort: none` (sin eso consume los tokens pensando), `max_tokens: 4000` y `response_format: json_object`. JSON-LD `JobPosting` gana; la IA completa campos y genera `datosClave`. `lib/helpers/job_page_parser.dart` maneja `@graph`, `addressLocality` en array, `baseSalary` sin valor y descripciones cortas. `lib/helpers/job_url.dart` normaliza LinkedIn search → `/jobs/view/<id>` y detecta posts/formularios. `lib/helpers/job_extraction_mapper.dart` mapea enums, salario (`formatSalaryOffer`), empresas placeholder y notas (`appendComment`). `lib/helpers/job_description_markdown.dart` compone la descripción como resumen Markdown (`Resumen`, `Responsabilidades`, `Requisitos`, `Beneficios`, `Observaciones`) a partir de las secciones que devuelve la IA, con etiquetas en negrita y tope de 3.000 como guarda; `lib/widgets/markdown_description.dart` lo renderiza con `flutter_markdown_plus` e iconos Material por sección (detalle y vista previa del formulario). `lib/helpers/job_duplicate.dart` compara el link canónico. La hoja (`import_application_sheet.dart`) captura y muestra el resumen; el formulario aplica solo sobre campos vacíos, marca secciones con `AiBadge`, permite “Vaciar IA” y confirma duplicados al guardar.
- **Análisis IA de empresas (opcional):** tarjeta **Análisis IA** en `CompanyDetailScreen` (entre Distribución y Vacantes) que analiza el comportamiento de la empresa en sus procesos de selección. **Solo a nivel de empresa**: la plataforma es solo el canal y se envía como dato (vacantes sin enlace → "sin enlace (posible correo)") para que la IA pueda mencionar matices por canal dentro del perfil. `lib/services/company_analyzer_service.dart` (`CompanyAnalyzerService`) arma el prompt y prueba los modelos de `AiConfig` con la misma política de respaldo (`aiShouldFallback` de `fallback_extractor.dart`); `lib/helpers/company_analysis.dart` calcula los hechos deterministas (`companyAnalysisFacts`: tasa de respuesta, días promedio a primera respuesta/cierre, estancadas ≥ `kUmbralDiasSinNovedad`, salarios, plataformas; `ultimaNovedadDe` considera seguimiento, postulación **y fechas de las notas**) y `isInsightStale` detecta el desfase; `lib/helpers/company_analysis_prompt.dart` (`kCompanyAnalysisSystemPrompt` + `buildCompanyAnalysisPrompt`, historial ordenado por última novedad, tope 25 postulaciones); `lib/helpers/company_insight_mapper.dart` (`mapAiCompanyInsight`) valida la respuesta (vocabulario cerrado de etiquetas, textos/listas recortados; análisis vacío → `JobImportException`). El resultado (`CompanyInsight`) se guarda en `EmpresaAnalisis` (`upsertCompanyInsight`) y en `LocalCache` (`devjobs_company_insights`); si el guardado en la Sheet falla se conserva local. Disparador **manual** ("Analizar con IA" / "Reanalizar"); con novedades desde `datosAl`/`totalPostulaciones` la tarjeta avisa "Datos desactualizados". La IA devuelve JSON con etiquetas (`kCompanyInsightTags`), `recomendacion` (Priorizar/Seguimiento normal/Baja prioridad/Precaución), `resumen`, `fortalezas`, `riesgos`, `perfilVacantes`, `procesoSeleccion` y `contactos`. Sin configuración de IA no se renderiza; offline el botón queda deshabilitado.
- **Models:** `lib/models/job_application.dart` — `JobApplication` (16 fields: rowIndex, empresa, vacante, tipoContrato, modalidad, ciudad, salarioOfrecido, estado, link, descripcion, fechaPostulacion, fechaSeguimiento, contacto, comentarios, entrevistaRealizada, porGestionar) + `DashboardStats` (total, activas, entrevistas, conRespuesta, finalizadas, porGestionar). `lib/models/company_insight.dart` — `CompanyInsight` (empresa, fechaAnalisis, datosAl, totalPostulaciones, etiquetas, recomendacion, resumen, fortalezas, riesgos, perfilVacantes, procesoSeleccion, contactos; `key` normalizada, `fromJson`/`toJson` con listas `- item` y etiquetas visibles, `tryFromJson` tolerante a filas de scripts viejos) + `CompanyRecommendation` (`parse` por etiqueta o id, desconocido → `seguimientoNormal`) + `CompanyInsightTag`/`kCompanyInsightTags`/`insightTagByValue` (vocabulario cerrado con tono positive/negative/neutral). `lib/models/application_options.dart` — opciones de los selectores (contrato, modalidad, estado) y estados finales (`applicationFinalStatuses`) compartidos por crear/editar y finalizar. `lib/models/ai_config.dart` — `AiConfig` (`baseUrl` + `apiKey` + `models` ordenada; `isEnabled`, `primaryModel`, `providerHost`, `validate`/`validateBaseUrl`, `copyWith`, `toJson`/`fromJson` con normalización de espacios y duplicados). `lib/models/job_import.dart` — `JobImportResult` (incluye `aiError`, el mensaje de la IA cuando no respondió), `AiJobData` (incluye `resumen`, `responsabilidades`, `requisitos`, `beneficios` y `observaciones`), `ParsedJobPage`, `JobPageKind`, `JobImportStatus`, `JobImportErrorKind` (incluye `notFound` para HTTP 404) y `JobImportException`.
- **Service:** `lib/services/sheets_api_service.dart` — HTTP client using `package:http` (`fetchAll`, `fetchDashboard`, `updateRow`, `create`, `fetchCompanyInsights` tolerante a scripts viejos y `upsertCompanyInsight`). `job_import_service.dart` — fetch + orquestación (acepta `AiConfig` para armar el extractor). `fallback_extractor.dart` — `FallbackExtractor` + `ModelExtractor` + `aiShouldFallback` (política de respaldo compartida). `openai_compatible_extractor.dart` — cliente OpenAI-compatible (`extract` para vacantes y `completeJson` genérico reutilizado por el análisis de empresas). `company_analyzer_service.dart` — `CompanyAnalyzerService`: análisis IA de empresas con respaldo entre modelos.
- **Screens:** `MainScreen` with `NavigationBar` (4 tabs: Inicio/Postulaciones/Empresas/Agenda). `PostulacionesScreen` = pills Todas/Activas/Enviadas/Finalizadas + `ApplicationsListScreen` (se remonta por `ValueKey(filter)` al cambiar de pill). Crear y editar comparten `ApplicationFormScreen` (`lib/screens/application_form_screen.dart`, constructores `.create()` y `.edit(app)`): secciones Vacante/Proceso/Notas, fechas con `showDatePicker` (solo calendario, locale es) y barra de guardado fija. El campo Empresa sugiere empresas registradas parecidas al escribir (aviso ámbar `form-empresa-suggestions` con chips "Usar …"; nunca automático, en edición excluye la propia fila) y ofrece el enlace `form-empresa-confidencial` **¿Sin nombre? ## Notes

- `.agents/` and `.kiro/` are gitignored (AI tool artifacts).
- No CI, no custom build scripts, no test fixtures.
- **Íconos en release:** Flutter tree-shakea `MaterialIcons` y algunos glyphs usados se descartan por un bug del tree-shaker (p.ej. `Icons.business_outlined` queda invisible). Por eso los builds release usan `--no-tree-shake-icons` (ver tabla de comandos).
- **Fechas:** nunca enviar `DateTime.toIso8601String()` ni timestamps (pueden correr un día en GMT-5); usar `formatApiDate`. El picker debe estar en locale es (`flutter_localizations`): en inglés la entrada de texto interpreta MM/DD/YYYY y produce el clásico intercambio día/mes.
- **RowIndex:** es posicional. Insertar o borrar filas en el Sheet invalida los índices cacheados; la app refresca al crear con `shifted == true` y con el TTL, pero tras editar el Sheet conviene hacer pull-to-refresh antes de editar en la app.
- **Widgets en `Stack` con `StackFit.expand`:** un error de build (p.ej. excepción en `build`) se pinta en release como un `ErrorWidget` **gris que cubre todo el `Stack`** y bloquea el toque. En `ScrollToTopButton` esto pasaba por leer `viewportDimension`/`pixels` antes de que el `ScrollPosition` tuviera dimensiones.
